# 乳腺癌全生命周期平台 · 全链路功能演示版

一个可本地一条命令启动、可反复演示的 Web 原型，展示"患者 → 医生 → 数据治理 → 药企研究 → 试验机会回到患者"的闭环。全部数据为合成数据，仅用于演示。

已增加上市后患者支持项目（PSP）的项目入口、独立授权、成员与固定计划、项目问卷提交/修订、联系记录、医生复核和教育阅读反馈，以及项目今日服药自报、不可变证据副本和联系补录核验。Task 5 已通过独立复审、完整测试与实际重启验收。Task 6 的纯计算指标与历史资格层已通过独立复审和最终集成验收：644 项单测、Next/Workers 各 27 项 E2E、安全构建/dry-run，以及实际重启后的来源、四组指标和 35 份原回执一致性检查。Task 7 的 k=5 联动保护、独立服务快照与内部来源追溯已验收：694 项单测、Next/Workers 各 31 项 E2E、安全构建/dry-run，以及实际重启后两个快照、冻结来源和 37 份原回执一致；独立复审 PASS / PASS。Task 8 已新增内部固定报告草稿与结构化下一期安排，验收记录见 [Task 8 报告](docs/superpowers/sdd-ledger/2026-10-15-psp-task8-report.md)。Task 9 已接通内部提交、数据/医学双签、退回修订，见 [Task 9 报告](docs/superpowers/sdd-ledger/2026-10-15-psp-task9-report.md)。Task 10 已实现双签交付、药企报告读取/固定文件下载、客户反馈/验收及当前授权门控，最终集成门禁与复核状态见 [Task 10 报告](docs/superpowers/sdd-ledger/2026-10-15-psp-task10-report.md)。当前 Task 0–11 已完成；Task 11 月报工作台、全线导航与签署时间线最终验收见 [Task 11 报告](docs/superpowers/sdd-ledger/2026-10-15-psp-task11-report.md)；Task 12 未完成；上述数字是对应任务当时的验收记录。

技术栈：Next.js 15（App Router）、React 19、TypeScript、Tailwind CSS 4、Recharts；单元测试 Vitest，端到端测试 Playwright。

## 环境要求

- Node.js 22.13+（含 npm；依赖声明的引擎范围为 `^20.19.0 || ^22.13.0 || >=24`，22.12 及更早的 22.x 不满足）
- 端到端测试需要 Playwright 的 Chromium（首次运行前安装一次）

## 安装与启动

```bash
npm install
npm run demo
```

- `npm run demo` 在 3000 端口启动开发服务器；首次启动若 `data/seed/cohort.json` 不存在，会先自动执行 `npm run seed` 生成种子数据。
- 打开 `http://127.0.0.1:3000/`。在 `localhost` 无法解析的机器上（例如 `/etc/hosts` 中没有 localhost 条目），请一律使用 `127.0.0.1`。
- 首页提供四个视角入口、**一键重置**（恢复到种子状态）、数据清单（种子、版本、checksum、截止日）与演示脚本链接（`/demo-script`，内容即 `docs/demo-script.md`）。
- 运行时状态（预警、任务、队列、快照、候选请求、补数任务、患者消息）保存在服务进程内存中；重启服务或点击一键重置即回到种子状态（一键重置同时清除浏览器里记住的演示患者、工作台身份与已读消息）。
- 种子数据：种子 20261013、生成器 gen-v4、数据截止日 2026-10-13、队列 checksum `cc3217fe1d251f10`；锚点 12 例 + 批量队列 2000 例（共 2012 例）+ 异常病例 20 例（只用于测试）。截止日之后不存在任何治疗、结局、问卷或打卡记录。详见 `docs/data-generation.md`。
- 更新生成器后，如本地已有旧的 `cohort.json`，先运行 `npm run seed` 重新生成数据，再重启演示服务器。

## 可选：模型配置

助手默认运行在 **本地演示模式**（确定性模板，数字由计算服务填充），无需任何密钥、断网也能完整演示。若要接入在线模型，复制 `.env.example` 为 `.env.local` 并填写：

| 变量 | 说明 |
|---|---|
| `DEMO_CLAUDE_API_KEY` | Anthropic API 密钥；填写后优先使用 Claude |
| `DEMO_OPENAI_API_KEY` | OpenAI 兼容接口密钥（未填 Claude 密钥时使用） |
| `DEMO_OPENAI_BASE_URL` | OpenAI 兼容接口地址，默认 `https://api.openai.com/v1` |
| `DEMO_OPENAI_MODEL` | OpenAI 兼容接口的模型名（使用兼容接口时必填） |
| `DEMO_FIXED_NOW` | 固定服务器时间，如 `2026-10-13T10:00:00+08:00`，保证演示话术与服务时段一致 |
| `DEMO_PERSIST` | 预留（落盘 SQLite），本版未实现 |

- 密钥只在服务端读取，浏览器不接触模型接口。修改 `.env.local` 后需重启 `npm run demo`。
- 无密钥、网络错误、401/403、429、超时（8 秒）或输出校验失败（含回复被 `max_tokens` 截断或被模型拒答）时，助手自动降级为本地演示模式，并在对话框顶部提示原因。右上角 ModeBadge 始终显示当前模式。
- 在线回复中的数字须复用服务端提供的带字段事实句（年龄、症状分级、随访日期、人数、比例分别校验），不能把年龄用于人数。指南引用须来自本轮检索；研究端只允许受控描述性事实，疗效/生存问题在所有模式下返回范围说明。未满足约束的措辞会降级为本地模板；患者/医生的非数字自由文本仍需专家审阅。
- OpenAI 兼容接口的 `finish_reason=length`、`content_filter` 或 `refusal` 也会降级。快照总人数、符合已知条件人数及明确的一线→二线、二线→三线统计在所有模式下都由服务端计算与呈现；其它线别或歧义问题返回范围说明。
- **演示前请用真实密钥试跑一次**：单元测试只用模拟的接口响应验证了 Claude / 兼容接口的调用流程，真实密钥下的模型名、配额与回复长度（`max_tokens` 1500）需要在演示日前用三个助手的快捷问题各试一遍。在线模式下每条回复只有两种结果：要么正文中的数字、引用与研究结论逐字复用服务端事实句，要么在对话框顶部显示带中文原因的降级提示（如「已切换至本地演示模式（输出未通过校验）」）并改用本地模板作答。两种结果都是预期行为，演示时按当时显示的模式讲解即可；若每个问题都降级，请先检查密钥、模型名与配额，再看降级提示中的原因。

## 测试

```bash
npm test                         # Vitest 单元测试
npx playwright install chromium  # 首次运行端到端测试前安装浏览器
```

- `npm run e2e` 会自动以 `DEMO_FIXED_NOW=2026-10-13T10:00:00+08:00` 启动 `npm run demo`；若 3000 端口已有服务则直接复用，因此请先停掉未设置 `DEMO_FIXED_NOW` 的服务，以免夜间运行时患者端反馈文案不同。
- 端到端测试共享同一个服务进程的内存状态，配置为单 worker 串行执行。

## PSP 演示（Task 0–11 已完成，Task 12 未完成）

1. 打开 `/pharma/projects`，进入 `PSP-BC-ENDO-001`。药企看到虚构项目范围、保护后的当前允许汇总人数和曾交付报告列表；初始无交付时显示暂无报告。每个已交付版本按当前授权显示可读或停止访问状态，内部草稿/审核候选不出现。此人数是当前授权概况，不是月报指标；小于 5 人时隐藏精确人数。
2. 打开 `/patient?patient=P-A`，在支持项目卡分别操作“接受支持服务”和“允许项目汇总”。撤回汇总授权不会停止服务；撤回服务授权会同时暂停项目成员。授权历史及既有固定计划保留。
3. 打开 `/clinic/projects/PSP-BC-ENDO-001/services`。初始 20 名候选中有 18 名有效服务成员，14 名允许汇总。邀请中的 `P-0040` 可打开患者视图先授权服务，再切换张医生确认适用性、切回个案管理师小陈激活。授权本身不自动激活。
4. 患者首页和 `/patient/plan` 显示固定问卷、联系及教育计划。点击“填写项目问卷”进入绑定计划的表单；联系由服务团队执行，已发送教育可进入阅读反馈。10 月项目问卷初始完成为 0。新加入者从固定 10–12 月项目日历选择各类型下一次未到期时间，当前固定时钟下为 11 月，不补造加入前逾期责任；原 18 人的 10 月计划保持原到期时间。
5. P-A 在 10:00 提交 09:00 截止的项目问卷后，计划显示“已完成 · 迟交”。答卷、既有规则预警/反馈、首次完成时间及最新答卷引用一次保存。相同请求重试返回原回执；普通重复填写不新增答卷或预警。显式“修订项目问卷”载入该计划最新答卷，创建新答卷并保留首次完成时间。网络/503 用“重试同一次提交”，409 刷新后核对计划。
6. 打开 `/clinic/patients/P-A` 的“PSP 联系、复核与教育”，切换个案管理师小陈。为两条项目预警分别接单、开始处置，勾选同一次联系覆盖两条预警；未接通只记一次失败尝试，原联系计划继续待办。一次接通可完成关联的常规联系计划，保持两个预警各自的状态与证据。
7. 两条预警分别填写处置类别、摘要并引用同一次联系，提交复核。切换张医生，分别填写复核意见和未来复评时间（上海时间），确认后各生成一个未完成临床任务及对应 PSP 跟进计划。复核关闭不代表症状改善。
8. 小陈发送已批准的固定教育版本。患者从首页、计划或消息进入资料，打开页面不自动记为已阅读；点击“我已阅读”后分别反馈“我已理解”和“仍需服务团队帮助”。需要帮助会创建一个未来联系计划，医生安排的未来临床复评仍待完成。
9. P-A 从患者首页支持项目卡点击“查看项目服药自报”，进入 `/patient/adherence?enrollment=ENR-01&patient=P-A`。只可提交上海今天的已服/未服（应服 1 次），发生与入账时间由服务器生成；与临床今日行一次保存不可变 PSP 值副本。再次修改须显式修订最新来源，旧值与来源继续保留。没有 enrollment 参数的 `/patient/adherence` 保留原通用打卡。
10. 从服务台点击“项目证据与补录核验”，或打开 `/governance/projects/PSP-BC-ENDO-001/corrections`。用个案管理师小陈身份选择成员，点击“导入历史日期副本”才会复制完整落在服务/授权窗口内的已结束日期；今天及日内中断/授权边界日期排除，真实导入时间记为入账时间。查看页面或 GET 不自动导入、核验或写入。小陈也可选择原始联系，填写补录渠道/结果、发生时间与原因，提交为待核验；切换“项目数据审核者”，逐项核对原/新值与两种时间后核验。核验值供未来新快照使用，不覆盖原联系、完成原计划或改动医生记录。

`/patient/pro?assignment=<计划ID>&patient=<患者ID>` 是项目入口，`/patient/pro` 保留原通用问卷；通用提交不会完成项目计划。项目提交必须有有效服务授权，汇总授权独立；授权撤回后新提交/修订被拒绝，已保存但丢失响应的请求可回放原回执。项目反馈按模拟自然小时目标呈现，并保留非服务时段/急症提示；原通用回执仍按原流程。

页面和接口中的角色/actorId 是明确标注的模拟身份，全部数据合成。PSP 使用独立 `psp-v1` fixture/checksum，不更改原临床 `gen-v4` 数据。临床研究同意不等于 PSP 授权；内部/患者/药企走专用 DTO，通用 state 不包含 PSP。

内部项目服务台可进入 `/governance/projects/PSP-BC-ENDO-001/snapshots`，由模拟项目经理或数据审核者按明确窗口冻结服务快照；医学审核者可只读查看。页面分别展示内部精确指标、受保护汇总预览及按指标展开的冻结来源。该预览只供内部核对；Task 10 药企入口只读取已交付报告的白名单投影，不开放内部精确指标、快照或审核候选。

Task 8 内部入口为 `/governance/projects/PSP-BC-ENDO-001/reports`，可从服务台“固定报告草稿”或所选快照“从此快照生成报告草稿”进入。项目经理选择冻结快照，保存七章节确定性模板；下一期安排只含类别、负责角色、上海时间和计划状态，可先留空并显示待补充提示。修订须显式选最新父版本，同期间可采用新快照，旧版正文与摘要保留。Task 9 已开放项目经理提交、数据/医学审核者签署和退回；安排内容对审核者只读。Task 9 当时尚无交付；Task 10 已追加项目经理交付按钮和药企最小报告页。报告数值仅来自快照的保护投影；内部精确来源单独展开。汇总来源授权撤回后拒绝新生成，历史内部草稿仍可核对；重新授权不会自动恢复旧来源。报告不依赖在线模型。

## Cloudflare Workers 部署

Git 构建已为 `med-test` 配置：构建命令 `npm run build:worker`，部署命令 `npx wrangler deploy`，项目根目录 `/`。推送到 `main` 后自动构建发布。采用 OpenNext 保留页面和 API，默认运行确定性助手，无需在线模型密钥。

```bash
npm ci
npm run build:worker       # 在隔离目录生成 gen-v4 数据并构建 Workers
npx wrangler dev           # 在 Workers 本地运行时预览
npx wrangler login         # 仅手动 CLI 发布时需要
npx wrangler deploy
```

运行时固定演示时间为 `2026-10-13T10:00:00+08:00`。仅将合成种子数据和公开演示脚本加入构建包；本地 `.env*`、`.dev.vars*`、生成包和账户凭据均不入库。静态资源由 Workers Assets 提供，未启用付费 R2 或在线模型。

`build:worker` 将源文件和已安装依赖复制到临时目录，递归排除 `.env*` / `.dev.vars*`、本地构建缓存及工作区；构建子进程仅继承必要系统变量，并使用固定演示时间。它拒绝外部源链接/依赖链接，不读取或移动原环境文件，也不替换本地 `.next`。构建后检查 OpenNext 三种模式的环境模块均为空、产物无 dotenv 文件，才更新 `.open-next` 和 `cloudflare/files.generated.mjs`；更新失败回滚两份产物，失败不触发后续部署。复制依赖需要额外临时磁盘空间，临时目录在成功或失败后清理；若输出备份恢复也失败，保留备份并报告恢复路径。

Workers 构建统一使用 `npm run build:worker`；`preview:worker` 和 `deploy:worker` 也调用这一入口。直接运行 OpenNext 构建不会经过隔离校验。需要验证部署打包而不发布时，可在安全构建成功后运行 `npx wrangler deploy --dry-run`。本地 `npm run demo` 的模型配置方式保持原样。

本次构建隔离与 lint 修复的验证记录见 [Worker 构建修复报告](docs/superpowers/sdd-ledger/2026-10-14-worker-build-env-fix.md)。

Workers 的 `/api/*` 统一经过一个 SQLite-backed Durable Object：跨实例访问使用同一份演示状态，并在请求结束前保存压缩快照；实例回收后恢复患者、预警、任务、研究快照和重置版本。静态页面及资源继续在边缘提供。它仍是**所有访问者共享的演示环境**，不是独立的多用户会话。首页“一键重置”会同时重置所有访问者的演示状态；勿在他人演示中操作。

Durable Object 使用 Free 支持的 SQLite 后端，未升级付费套餐。存储按 gen-v4 与全部种子文件的 SHA-256 分开；将来改变业务状态结构须迁移版本，不能直接复用旧快照。压缩存储值上限设为 2 MiB，超过时需重置演示。

PSP 第一阶段的持久化 payload 为 schema v2，存储键为 `demo-v2-<临床版本>-<全部种子指纹>`，PSP fixture 和 manifest 均参与打包与指纹。旧 v1 共享演示进度会在升级后重新初始化，不进行隐式迁移；Durable Object 类和迁移标签保持原配置。恢复会严格校验临床及 PSP 状态，并重新冻结研究快照和已批准教育内容。接口在持久化成功后才返回成功；写入失败会重读持久化结果，恢复无法确认时返回 503 并阻止后续操作，直到恢复完成。同一次失败操作可用原请求编号重试。
