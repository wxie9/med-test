# PSP Task 4：联系、医生复核与教育反馈闭环

日期：2026-10-15；基线 `4b4a23d`。用户授权完成 Task 4、验证并本地 commit。独立分支 `codex/psp-services`；Task 5–12 不在本轮范围，不推送或部署。

## 实现与口径

- 患者项目问卷仍使用 Task 3 的原子命令。临床患者详情新增当前姓名、模拟身份清晰的 PSP 服务区；服务台成员可直接打开患者详情。已识别项目预警从该详情原操作队列移至 PSP 专用操作区，通用临床与研究支线继续保留。
- `recordInteraction` 一次记录一个电话/消息联系事实和互斥结果，可同时引用本患者项目的多个预警、可关联一个未完成固定联系计划。未接通、拒绝、渠道不可用均不完成计划或关闭预警；接通仅完成选中联系计划，一次电话覆盖两条预警仍只有一个 interaction。发生时间可合法补记，入账时间来自服务端，两者分别保存并验证当时服务授权。
- 每条预警分别接单、开始处置、提交结构化处置，再由医生复核关闭。继续以原临床状态机为唯一状态执行者；PSP 另留不可变动作事实，开始处理不会自动拥有处置或医生复核证据。处置须填写类别/摘要并引用覆盖该预警的真实联系。
- 医生填写必需复核意见、未来任务类型/责任人及明确选择的上海时间。精确 `dueAt` 必须晚于 `max(复核时间, 项目cutoff)` 且在项目结束前；同一事务保存关闭、复核记录、临床未来任务/原计划消息及对应 PSP 跟进计划。临床任务仍为 open，日期取上海 DateOnly；每个复核独占其任务/计划引用。关闭不能推断症状改善。
- 个案管理师只能发送已批准且批准时间有效的固定教育内容版本。发送后版本不可改，发送/明确阅读/反馈各留独立事件；打开 GET 或渲染页面不写阅读事实。患者分别反馈理解与帮助需求，“仍需帮助”只创建一个未来 PSP 联系计划，不能完成医生安排的未来临床任务。
- 患者首页、计划和消息提供本患者已发送资料入口。当前服务授权撤回后保留历史只读，汇总授权不决定服务。实际完成时间与合成背景分别展示，问卷按时/迟交仍由首次有效提交决定。

## 事务、访问与兼容

- 新联系、预警动作与教育命令使用同步隔离副本，先检查 seed、模拟身份及对象范围，再回放同内容请求回执，最后检查目标版本、当前服务条件并写入。接单/处置/教育不增加授权版本；同一请求换内容拒绝。历史回执单独深复制，不随教育后续阶段的实时投影变化。
- 新接口为内部患者服务 GET、项目 interactions POST、PSP alert actions POST、教育 GET/POST。患者教育 GET 只返回本人绑定内容/结果；内部服务 DTO 只含当前成员信息；药企仍走汇总专用 DTO，未新增患者明细或月报指标。
- 界面复用带 scope/token/seed 守卫的项目状态钩子。503/网络失败保留同一次完整请求并锁定输入，409 刷新后核对；切换患者/角色或 reset 不展示旧成功、失败或重试入口。
- 保持 schema v2 和存储键；新临床 alert.version 与 PSP alertActions/educationEvents 为可选字段，不默认改写旧 fixture。临床 gen-v4 与 PSP psp-v1 文件未改；旧完整教育背景记录及旧联系背景仍可读取并标识。
- 提交、encode 和 decode 均验证项目/患者/计划归属、历史授权、事件时间/顺序、完成投影、处置引用、临床意见/消息、独占任务引用和固定教育版本关联。后来正常完成跟进不被当作存储损坏；错误跨事实引用拒绝持久化。
