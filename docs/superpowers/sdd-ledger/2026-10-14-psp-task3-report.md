## 实现

- 从患者首页/固定计划进入 `/patient/pro?assignment=<稳定计划ID>&patient=<患者ID>`。核对当前患者、所属项目、固定截止、服务授权与计划状态；无效/跨患者计划不回落到通用表单。原 `/patient/pro` 和临床接口保留，普通问卷不计项目计划完成。
- 新增严格 `POST /api/psp/assignments/[assignmentId]/pro`，与原 PRO API 共用题项/flag 校验。执行顺序为 seed、模拟身份和对象归属 → 既有同内容回执 → 计划版本/当前授权与窗口 → 副本内临床与项目变更 → 完整关系校验 → 提交。问卷使用 assignment 版本，患者成员与授权版本不因填报而变更。
- 同一同步事务保存临床 PRO、原规则预警/反馈、计划完成、首次有效提交及最新答卷引用和幂等回执。不会先调用通用接口再补项目关联。P-A 10:00 对 09:00 截止计划提交会完成一次并保持迟交；本阶段不生成报告或指标模块。
- 相同请求重试回放原回执，不新增答卷/预警/消息；已完成计划的新请求普通提交返回既有有效结果，计划版本不增长。显式修订须引用最新有效答卷，追加临床记录与适用的预警/反馈、更新最新引用，首次完成时间不变。修订关系以可选 `ProResponse.revisionOf` 持久化。
- 项目反馈使用模拟高风险 2 / 中风险 24 自然小时目标，保留非服务时段与急症提示。原通用回执及原预警规则未改。汇总授权不影响患者服务；当前服务授权撤回后新写入被拒绝，已提交请求的丢失响应重试仍可回放历史回执。
- 表单绑定患者、计划、seed 和修订目标。切换/重置/卸载后丢弃旧成功及错误；409 刷新并要求核对，网络/503 保留同一完整 body 和请求编号重试。待确认期间禁用编辑与重复提交。修订预填按计划最新答卷 ID 精确读取，不取患者最后一份通用答卷。
- 持久化继续使用 schema v2 / 原存储键。可选 revisionOf 没有默认值，旧数据兼容；原临床/PSP fixture 与两个 checksum 均不变。事务、encode 和 decode 校验计划完成字段、最新答卷归属/量表/完整内容、时间及同患者修订链，拒绝缺失/错误/循环引用。
