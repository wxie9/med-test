# PSP Task 10：报告交付、客户反馈与当前授权门控

日期：2026-10-15；实施起点 `9027c2dea383dd7c9e7e77957dba865cc9eb6845`。本轮接通双签后的交付、药企读取/下载、客户修改请求/验收和授权撤回。完整签署时间线及全面工作台仍属 Task 11。

## 操作路径

1. 内部入口 `/governance/projects/PSP-BC-ENDO-001/reports`：项目经理选择已双签通过的最新版本，点击“交付此报告版本”。仅一签、旧版本或当前汇总来源不可用时，服务端拒绝。
2. 药企入口 `/pharma/projects/PSP-BC-ENDO-001`：只列已发生交付的报告；内部草稿/审核候选不出现。由报告链接进入预览，读取和下载都重新校验当前授权。
3. 客户可填写意见并验收，或填写必需理由请求修改。修改请求使原版成为 `client_changes_requested`；项目经理选择最新父版生成新 revision，重新提交、双审与交付。验收与交付分别留记录，验收不代表所有指标达标。
4. 当前来源授权撤回后，旧版业务状态及内部内容保留，外部只显示停止访问状态。项目经理重新冻结可用范围，并以受阻旧版为父版生成新报告；新版重新双审交付。

新增[药企报告页](../../../components/psp/PharmaReport.tsx)是最小操作界面，沿用现有语义表单及窄窗口重排。完整时间线没有提前实现，身份、渠道与全部数据仍为合成演示。

## 状态、版本与固定交付

[交付服务](../../../lib/psp/delivery.ts)扩展 `approved→delivered→accepted/client_changes_requested`。提交/审核/交付/客户反馈均核对 `report.version`；创建修订继续核对项目 `ledgerRevision`。PM交付只能走内部 actions，药企 actions只接受 accept/request_changes。原编号同体返回原回执，新编号重复动作或旧版本竞争拒绝。

可选 `reportActions` 扩展交付和客户事件，新增可选 `deliveryArtifacts`；schema v2、存储key和种子不变，无默认补数组。报告本体只推进状态/版本，不添加会污染旧创建回执的后添字段。生命周期按完整事件前缀重建，创建、提交、首签、交付和客户回执各自保持当时结果。外部动作回执只含状态元数据，撤回后重试也不返回旧正文。

[固定交付文件](../../../lib/psp/deliveryArtifact.ts)仅从白名单正文、结构化安排、两类角色/签署时间及交付时间生成中文文本，保存确切UTF-8字节及SHA-256。客户意见、验收状态和当前gate不进入原文件。文本下载返回原字节；HTML对同一固定文本转义包装。恢复时重新校验正文、事件绑定、摘要和字节并深冻结，接受/修改请求都不能改已交付文件。

## 当前授权与新快照范围

`authorizationGate` 的 eligible/blocked/revoked与业务生命周期独立：未交付且来源不可用为blocked，已发生交付后不可用为revoked。后来验收或客户退回不改变“曾交付”事实。[统一门控](../../../lib/psp/reportGates.ts)检查冻结汇总实际采用的grant区间，不按内部18人的名单一律撤销。服务授权单独撤回保留合法汇总历史；汇总重新授权不能恢复旧版已撤回区间。

新冻结采用可选 `aggregateAuthorizationPolicy: current_grants_v1`，通过[纯授权投影](../../../lib/psp/aggregateGrantProjection.ts)排除截至冻结时已被withdraw终止的汇总grant，仅对aggregate计算采用，internal历史及原始来源账保持原样。发生/入账时间、冻结账前缀和同钟sequence共同确定可见性；撤回晚于统计cutoff但早于freeze仍会终止旧区间。新grant只支持后来发生的合法事实，不追溯授权旧事实。

策略参与快照摘要、来源资格和恢复校验；旧无标记快照保持原语义及字节，不在hydrate时迁移。实际场景中撤回P-A后，新快照内部仍18、允许汇总范围13，旧14人报告保持原内容并停止新访问。已受阻的最新approved/delivered/accepted父版可选新的可用快照创建子版；健康终态版保持不可修订。

## 外部白名单与异步边界

概览、报告、下载、未来受控事实包入口及交付均调用当前gate。外部不展开内部report/workflow/snapshot：去掉患者/来源/事实ID、审核actorID、内部备注和审核退回理由，仅保留受保护正文、窗口/版本、角色时间、交付及客户自己的反馈。受阻响应没有旧正文、窗口、摘要、签署或文件；事实包另去掉客户自由文本，不新增在线模型。

报告和下载请求绑定project/report/period/seedVersion/authorizationVersion及模拟药企身份，拒绝多余/重复query。成功、错误及下载均no-store；失效版本错误仅给当前版本元数据及说明。下载采用服务端重新门控的链接，没有保留客户端blob。

共享hook维护按作用域绑定的seed/auth单调下限，新seed可重启较低授权序号，旧seed/较低auth响应不能恢复正文。外部读取错误清除旧内容；详情收到更高版本时通知概览，父gate改变立即卸载旧详情，URL/token隔离迟到响应。客户操作保持503原请求重试、409成功刷新后人工核对。独立评审发现的失败POST授权元数据缺口已修复：GET/POST共用单调版本观察，解析后重新检查当前操作，较高授权/seed立即清除旧内容及重试。60项相关回归与原始缺陷探针通过，范围复审PASS/Approved。全分支复审另发现详情版本下限在父级503卸载后丢失，以及存储协调器503缺no-store：已增加稳定父级版本屏障，在刷新前安装实际seed/auth，并按项目/报告访问隔离旧回调；存储层生成的503也明确禁缓存。77项定向回归及两个原始探针通过，最终独立复核Spec/Quality均PASS，未关闭问题为0。
