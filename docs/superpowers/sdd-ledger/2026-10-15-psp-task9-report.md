# PSP Task 9：报告提交、双审核与退回修订

日期：2026-10-15；实施起点 `399d2c5103d8135d79ce3893bf003b4a01de3f10`。本轮实现内部提交、数据/医学双审核、业务退回与重新修订。交付、下载、药企报告读取和客户验收属 Task 10；完整时间线属 Task 11。

## 操作路径

入口仍为 `/governance/projects/PSP-BC-ENDO-001/reports`，从项目服务台或冻结快照进入。选择报告后显示实际工作流及角色可用操作。

1. 项目经理选择草稿，提交报告审核。空安排仍允许提交并提示待补充，供审核者作真实业务退回。
2. 数据和医学审核者分别操作，顺序任意。首签保持审核中并明确待补哪一签，两签均通过才显示“双签审核通过（尚未交付）”。无第三个项目经理批准步骤。
3. 审核中任一审核者可填写理由退回。原版保留正文、快照、已有签署与退回理由，状态为待修订。
4. 项目经理选择最新退回版创建新 revision，补充结构化安排，重新提交并完成两类审核。新版本不继承旧签署；同期间可用原创建表单另选新快照。

[审核操作区](../../../components/psp/ReportReviewPanel.tsx)和实际签署/退回信息均位于固定正文之外；正文保留生成时的模板标记，以独立工作流显示当前状态。内部来源仍按固定 snapshot 核对，不把审核理由加入报告正文。药企入口继续不显示内部报告候选。

## 版本与命令

[服务](../../../lib/psp/review.ts)提供 submitReport、reviewReport、reviseReport，统一 POST `/api/psp/reports/:reportVersionId/actions`。严格区分两类 CAS：提交/审核用 report.version；创建修订用项目 ledgerRevision，与 Task 8 一致。提交 draft/v1→in_review/v2，首审v2→v3，次审v3→approved/v4。并发两审同expectedVersion时只一成功，另一409后刷新补签；保留第一签，不覆盖数组。

只能操作 batch 最新头；审核中/批准版不可修订，最新 draft 或 changes_requested 可创建新版本。旧版有子版本后不可再提交/审核；同编号原回执仍可重放。修订沿用唯一 create_report 归一化回执，不嵌套创建第二份回执、不改变父版版本。提交/审核每次一事件、一回执、一项目账序号，不改变成员或授权版本。

数据/医学 kind 必须匹配预置身份。批准不接受额外理由字段；退回理由 trim 后必填、最多1000字符。新编号重复同角色批准拒绝；原编号同体返回原完整结果，换体400；旧 seed 和错误身份先拒绝。路由拒绝多余字段/query，成功及错误均 no-store。

## 两签绑定与历史恢复

新增可选 `psp.reportActions`，严格 submit/review 事件，不预填旧状态、不变更 schema v2、种子或存储 key。每个动作绑定 project/seed/reportVersionId/报告revision/snapshotId和摘要/contentDigest/模板/算法/保护版本、执行人、时间、账序号与动作前后对象版本。

两签共享 submissionId 与提交后 submittedVersion=2；各自 CAS 前版本2/3不混作共同签署版本。[纯投影](../../../lib/psp/reviewProjection.ts)从初始 draft/v1 按事件顺序重建状态、签署和退回。当前状态必须与投影一致。动作序号参加现有全业务序号唯一性校验，并与命令回执逐一对应。

Task 8 创建回执永远保留原 draft/v1 结果，不随着当前状态更新。每个提交/审核回执按其事件前缀重建当时的完整 CommandResult；首签在双签之后、创建在退回修订之后仍精确重放。[恢复校验](../../../lib/psp/reviewValidation.ts)拒绝孤立/重复事件及回执、签署绑定变化、非法状态顺序、角色错配、跳版本、账序号碰撞、错历史结果和非法父版本前缀。原 contentDigest 域不变，正文继续从固定受保护快照重新生成校验；hydrate 深冻结报告和追加事件。

提交前重新核对固定正文、来源和当前汇总授权。历史恢复只按提交当时的时间与账前缀验证授权；后来撤回不破坏合法历史或旧回执。内部审核可继续核对已提交的固定对象；新提交及新修订仍受当前来源授权限制。对外交付及每次读取门控由 Task 10 实现。当前持久化校验验证语义一致性，不提供对整份合法历史重写的外部真实性签名。

## 界面可靠性

详情作用域统一管理审核写入状态，待重试或待核对时同步锁住创建表单、版本选择、修订快捷按钮及审核区，避免独立 hook 互相绕过。503 重试保留原 body/meta/requestId；409 使用独立冲突epoch，不依赖提示文字。刷新失败或尚未完成时保持锁，成功读取后仍须人工确认；重复冲突重新核对，旧请求/token/seed不能伪造已刷新。身份、seed 或报告切换隔离迟到响应；报告版本推进后刷新父列表。安排表单对审核者只读，工作流操作按服务端 actionGates 显示，不在客户端重写状态机。
