日期：2026-10-15；实施起点 `5142ff4ff2e81a4ca054ad1d67481b7463e6f6c6`。最终独立复审及全部运行门禁通过。本轮只实现内部草稿创建、查看、修订和下一期安排。双审核、提交锁定、交付、药企报告读取、下载及客户验收仍属 Task 9–12。

## 入口与演示

内部入口 `/governance/projects/PSP-BC-ENDO-001/reports`，可从项目服务台“固定报告草稿”或所选冻结快照“从此快照生成报告草稿”进入。

1. 在服务快照工作台按固定阶段窗口冻结，再进入报告页。
2. 模拟项目经理选择冻结快照，点击“生成模板草稿”。空安排允许保存，并明确提示“下一期服务安排尚未补充，待人工审核”。系统不猜测行动或制造错误临床数字。
3. 在已保存列表选版本，可见七章正文、摘要、快照及独立工作流。数据/医学审核身份目前只读；签署、交付、验收均显示尚未执行。
4. 点“以此版本创建修订”，补充类别、负责角色、上海时间和安排状态；保存为下一 revision。也可选择相同报告期间的新快照。旧版始终保留，不原地覆盖。
5. “内部来源核对”单独读取所选报告对应快照的 aggregate 来源，精确来源不属于报告正文。药企入口仍不显示候选草稿。

## 固定正文与绑定

[模板](../../../lib/psp/reportTemplate.ts)为 `psp-report-template-v1`，七章依次是项目范围、数据说明、服务执行、患者反馈、质量与限制、下一期服务安排、审核与交付。项目/日期与安全说明来自固定白名单，40 项事实全部来自快照的 `protectedMetrics`。不复制原始 applicability、自由文字、精确来源、内部18人/差额或隐藏数字。已保护、未知、无适用和已知零分别表达；可用值缺失不回填零。报告不用在线模型，不导入临床 chat provider。

保存 snapshotId/snapshotDigest、项目/seed/期间、算法 `psp-metrics-v1`、保护 `psp-k5-v1`、模板版本、实际采用 factIds、父版本及创建记录。factId 由 snapshot + aggregate + metric key 形成。`contentDigest` 绑定正文、行动、事实和冻结来源版本；实际签署/交付/验收投影与生命周期元数据不进入正文摘要。第七章的静态说明属于正文，当前真实工作流另返回 draft、无签署/交付/验收。

[恢复校验](../../../lib/psp/reportValidation.ts)从固定快照与结构化行动重新生成正文，再比较精确内容、单位、章节、factIds、版本与摘要，拒绝攻击者重算 digest 后的正文篡改。hydrate 深冻结报告及嵌套事实、安排；GET 返回独立副本，不因后续联系/问卷/补录或当前权限改变而重算旧版。

## 安排、修订与命令

每条安排严格为 `{category,responsibleRole,dueAt,status}`，最多12条，无患者字段或自由文本。七类覆盖逾期、问卷、联系、医学复核、教育反馈、数据质量、项目统筹；临床支持交个案管理师，医学复核交医生，数据质量交数据审核者/PM，统筹交PM。状态仅 planned/in_progress，不证明临床或服务完成。必须含时区，晚于快照 cutoff 且在项目服务期内；UI 明确上海时间并保留父安排秒/毫秒精度。旧版日期按其固定 cutoff 校验，不随今天变化。

[服务](../../../lib/psp/reports.ts)仅 PM 创建/修订，PM/DR/MR 读取。一个项目与规范化期间只有一个稳定 batch；已有 batch 必须显式选择最新父版本，revision 连续增长，不能分叉。统一使用项目 ledgerRevision CAS；一次创建只新增一份报告与回执并前进一个项目账版本，不改变成员或 authorizationVersion。报告创建序号参加全局业务事件唯一性校验，不能与授权事件、补录核验、计划出生等共用序号。

幂等 scope 绑定 seed/project/create_report/actor/requestId，正文规范化包括 snapshot/parent/actions。旧 seed 和身份先校验，同编号换体拒绝；原回执重放先于 CAS、当前授权与最新父版本规则。即使后来撤回授权或生成新版，同一次原请求仍返回完整原 CommandResult，不增加业务记录。新 API 严格拒绝多余/重复 query、PHI字段与错误角色，成功和错误均 no-store。

## 新生成的授权与旧历史

[授权 helper](../../../lib/psp/snapshotAuthorization.ts)只检查冻结 aggregate 的实际直接事实、分母 cohort 和资格见证使用的历史 grant 区间；不把整个 snapshot.sources 的内部成员或仅支持引用当贡献。使用发生/入账时间与同钟 sequence，覆盖期间/截至成员、到期分母、提前完成、预警 cohort、自报日期级来源及核验更正。

已用汇总授权区间后来被撤回，新生成被拒绝；再次 grant 或重新冻结相同旧范围不恢复旧区间。只用新 grant 区间的新范围可生成；服务-only 撤回、非贡献者或无关授权版本变化不自动封禁。旧草稿内部读取、持久化和原回执仍保留。少数非 early 的旧问卷 unknown 来源没有精确缺口资格起点时，若可能跨撤回区间则保守阻止新生成；不从当前临床数据回填。此 helper 是 Task 8 创建门控，不冒充 Task 10 的对外交付/读取门控。
