## 1. 目标与第一批范围

首要用户：接收阶段报告、参与项目沟通与验收的模拟药企项目负责人。典型场景：办公室电脑上查看本期交付，或会议中使用窄窗口对照报告，需要迅速理解服务范围、可评价结果、证据限制、下一期安排及当前应做的动作。

本批采用“已有页面分层阅读”方案：两个现有业务页面中的三个区域——项目概览、报告阅读、客户验收。现有项目列表只做入口和文案衔接，不新增路由或独立经营仪表盘。

| 路径 | 收益与代价 | 本批决定 |
|---|---|---|
| 现有概览/报告分层 | 复用现有授权投影、固定事实和回执，集中解决阅读与验收 | 采用 |
| 独立实时绩效仪表盘 | 需另定义实时口径、范围与披露，当前概览 metrics 明确为空 | 后置 |
| 在线 AI 月报总结 | 需独立事实约束、验证及审核机制，现报告是确定性模板 | 后置 |

交付保真度为文字与信息结构设计，不制作高保真视觉图或交互代码。视觉沿用当前白底、系统中文字体、洋红强调和已有表单控件；以现有项目详情、快照口径展开、签署时间线为界面锚点。属于既有界面的信息层级细化，无需新视觉方向探针。

本批完成后的核心任务：客户进入项目后知道服务与交付范围，进入报告后理解可评价结果及限制，最后能找到核对依据并记录验收/修改意见。

## 2. 已核实的数据边界

- `PharmaProjectView.metrics` 当前为 `[]`；项目页不能呈现不存在的实时绩效。
- 项目概览可用：`project`、`allowedMembers`、曾交付版本的 `reports`。当前汇总授权人数不是固定报告的统计分母。
- `PharmaReportView` 只有 gate=available 才包含窗口、修订、正文、公开签署、固定文件、下一期安排和客户反馈；blocked/revoked 返回的基础字段不能补出这些详情。
- 外部正文已去掉内部 fact ID 等来源标识。阅读提要只能使用当前可读的这一份外部 DTO，不能调用内部指标、成员、快照来源或其他未交付版本来补全。
- 下一期安排最多12项，仅有类别、负责角色、时间及 planned/in_progress；不能显示为实际完成或承诺新的预约。
- 当前验收请求记录报告、动作、客户意见及原始命令回执；没有逐项勾选记录。本批不新增这种持久化声明。

参考：[药企投影与门控](../../../lib/psp/pharmaView.ts)、[报告事实与安排类型](../../../lib/psp/reportTypes.ts)、[报告模板目录](../../../lib/psp/reportTemplate.ts)。

## 3. 区域 A：项目概览——先说明服务和交付

沿用 `/pharma/projects/[projectId]`。

由上至下：

1. 项目名称、合成/模拟标识、资助方与服务人群。
2. 服务范围：计划问卷、服务联系、必要时医生复核、批准教育及患者反馈；标为本演示支持的服务内容，不虚构新频次、机构、SOW版本、预算或已签合同。
3. 周期和阶段截止，明确当前是阶段数据。既有高/中联系目标继续标为演示配置。
4. 本阶段交付说明：受保护阶段报告、数据/医学签署记录、固定文本/HTML、下一期安排与客户反馈。描述交付构成，不表示当前已完成。
5. 报告列表：每个曾交付版本的当前访问/业务状态、阶段截止及明确入口。
6. 当前允许汇总概况与用途说明；院内演示切换作为次级演示入口。

状态与主动作：

| 状态 | 主要内容 | 主动作 |
|---|---|---|
| 无交付 | “本阶段尚无已交付报告。完成双审核并由项目经理交付后可在此查看。” | 不生成虚假的客户报告入口；院内演示入口仍为次级导航 |
| 可读已交付 | 对应阶段与修订，“已交付，待客户反馈” | 查看本次交付 |
| 可读已验收 | 对应阶段与修订，“客户已验收” | 查看验收记录 |
| 客户请求修改 | 对应公开修改反馈状态 | 查看修改请求 |
| 访问停止 | 仅显示当前gate原因及重新核对入口 | 查看访问状态 |

`allowedMembers` 隐藏时只呈现既有理由；不展示内部18人、候选20人或内外差额。项目页不自动拼接报告指标，不混合不同窗口/修订，不在不可读报告被撤回后默认展示旧版作为替代。报告顺序首版沿用现有投影，不新增未经确认的“最新可用”选择逻辑。

## 4. 区域 B：报告阅读——业务内容在前，核对材料按需展开

沿用 `/pharma/projects/[projectId]/reports/[reportVersionId]`。由上至下：

1. 当前交付状态、修订、阶段开始至cutoff、交付时间；明确上海时间和阶段数据。
2. “本版阅读提要”：固定报告范围、重点披露指标、证据限制。
3. “下一期服务安排”：使用当前报告的 `nextActions`，显示类别、负责角色、时间和计划状态。
4. 三项交付核对提示与本状态主要动作。
5. 完整七章指标与口径，按业务章节可展开；所有40项仍可到达。
6. 本修订公开签署/交付/客户反馈时间线；固定下载；展开后的核对资料。

### 4.1 阅读提要的固定规则

提要是本版外部事实的确定性阅读呈现，不新增在线模型，也不形成另一份可变的业务报告。候选重点指标固定为：

| metricKey | 显示名称 |
|---|---|
| questionnaire_completion | 到期问卷完成 |
| contact_completion | 到期计划联系成功 |
| education_completion | 到期教育反馈 |
| service_completion | 到期服务任务（联系+教育） |

冻结的人群范围可用 `period_members` 辅助说明，来源是本版报告；不得用项目当前的 `allowedMembers` 替换。`active_members` 及其余指标在完整指标区保留。显示内容一律取对应 fact 自带标签、单位和保护后结果，不自行重算分子/分母、百分比、未完成数、完成率等级或跨期变化。

| fact状态 | 短文案 | 不能附带的推断 |
|---|---|---|
| available | 原有数值/分子分母及单位，口径可展开 | 无合同目标时不判断达标/未达标 |
| suppressed | “已保护 · 本项不展示精确结果” | 不用表现好坏、红黄绿或自然语言泄露隐藏值 |
| unknown | “证据不足 · 本项暂不能判断” | 不补0、猜分母或自动宣布缺少某种患者事件 |
| no_applicable | “本阶段无适用样本” | 不转为0%、不称任务失败 |
| 目录内事实缺失/类型不符 | 显示无法读取该项并提供重新核对入口 | 不取其他scope、其他版本或临床记录补齐 |

当前演示报告的示例呈现为：问卷“已保护”，联系9/14、教育9/14、服务任务18/28。这些仅用于设计说明，不能写死到组件或冒充后续任意报告的结果。

完整指标保留各项独立状态。重复定义可以归到章节说明与各指标“查看口径”；可到达性、键盘焦点及原始定义可核对性必须保留。若去重后会丢失某项特有定义，保留该项原文。

### 4.2 当前状态与原始生成标记

- 当前交付状态为首要状态；生成标记单列为“原文生成记录”，默认收起并可展开。
- 原文中的“模板草稿，待人工审核”必须明确标为生成时原始文字，不能继续充当已交付/已验收页面的当前状态。
- 本批不改 `content`、`contentDigest`、`artifact.text`、文件摘要、模板版本或已交付文件。原始正文与下载保持可核对。
- “正文摘要”改为“内容校验码”，“固定下载摘要”改为“文件校验码”；完整校验码与模板/算法/保护版本进入核对资料展开区。
- 首屏“签署已齐备”只取现有两类签署事实。时间线显示对应角色与时间，不暴露内部审核actor、退回理由、未交付父版本或内部来源。
- 下一期安排为空时，阅读区写“本版未列下一期服务安排”；原始正文里的生成时说明仍保留在原文。安排存在时维持planned/in_progress语义，不显示“已完成”。

本批不新增PDF、独立封面文件、ZIP或新签章凭证。若以后要生成独立交付封面，应另定义保存、签署与字节固定规则；不能临时包装后声称它也是已有固定交付文件。

## 5. 区域 C：客户核对与验收——明确核对什么

放在同一报告页面较靠前的位置，通过现有页内导航进入。使用“交付核对提示”，不新增必须勾选的checkbox，也不声称已逐项记录客户阅读或确认。

| 核对提示 | 查看依据 |
|---|---|
| 范围与阶段 | 本版项目范围、统计窗口和cutoff |
| 本版签署与固定文件 | 两类公开签署、交付时间和既有文本/HTML下载 |
| 服务记录限制及下一期安排 | 已保护/未知/无适用说明，以及当前nextActions |

这些行是阅读导航，不自动宣称“客户已阅读”“数据全部正确”或“目标已达标”。

| 当前状态 | 主要动作 | 操作后反馈 |
|---|---|---|
| delivered且当前可读 | 核对本次交付；核对区提供验收此版本 | 保存当前版本验收意见/时间，进入accepted |
| delivered且当前可读 | 次级动作：请求修改，理由必填 | 显示本次修改请求，等待服务方新修订 |
| accepted且当前可读 | 查看验收记录 | 展示既有验收时间/意见，固定下载可继续使用 |
| client_changes_requested且当前可读 | 查看修改请求 | 保留修改理由，不重复验收、不模拟新版已完成 |
| blocked/revoked或当前读失败 | 重新核对访问状态 | 不显示旧正文、提要、安排、文件或反馈入口 |

“验收此版本”和“请求修改”沿用现有服务端动作、版本校验与回执。验收意见当前可选的语义不变，请求修改理由仍必填。保存中、503重试、409核对、新seed/授权版本隔离均保留；不能为排版重构卸载原请求owner或回放成新请求。

用户文案：

- 验收前：“验收确认本次交付范围；意见单独记录，固定交付内容保持原版本。”
- 验收后：“本版本已验收。下期安排继续按实际进度执行，验收不代表安排已完成。”
- 修改请求后：“修改请求已记录，等待服务方生成新修订并重新审核。”

## 6. 信息结构与交互约定

沿用现有浅色界面与控件，不做品牌重绘。每个状态一个主动作；刷新、下载格式、模拟身份切换及核对资料采用次级样式。

成功阅读状态的轻量刷新优先作用于当前报告；项目/授权读取失败时提供对应重新核对入口。现有父/子读取职责、授权失效通知和操作owner不因按钮外观合并而改变。

业务章节默认展开阅读提要和下期安排，完整指标及核对资料按需展开；展开项要有清楚名称、键盘操作、aria-expanded及焦点落点。390px单列，755px窄窗口可自然换行，1440/1920px保持可读行宽。校验串只在展开区换行，不挤压业务文字。禁止横向溢出或仅靠颜色表达保护/未知/成功。

原有页内锚点 `public-report-body`、`public-report-timeline`、`public-report-feedback` 保持有效；新增阅读提要不能让原链接落到隐藏且无法打开的区块。

## 7. 关键状态与失败边界

| 情况 | 设计要求 |
|---|---|
| 初始无报告 | 清楚说明等待什么交付，不展示模拟绩效数字 |
| 可读的delivered/accepted/client_changes_requested | 按对应状态组织动作，阅读事实来自这一份当前外部DTO |
| 只有保护项/无适用/未知 | 展示三种状态差异与原因，无空白假成功，无精确值回退 |
| 读取失败或授权核对中 | 提要与正文一起失效；不保留已展开区里的旧数值或可点击旧下载 |
| 授权撤回后迟到旧GET | 新增提要/安排/提示也必须拒绝旧响应回显，不能成为现有门控之外的缓存 |
| 客户提交503/响应丢失 | 保留当前意见与原请求，使用原有精确重试 |
| 客户提交409 | 刷新并人工核对当前版本后继续，不自动覆盖或连续新建请求 |
| reset、换项目/报告/授权版本 | 完整退休旧读取/操作作用域，不跨版本复用提要 |
| 多报告、某一版本不可读 | 逐项遵循自己的gate，不用另一个报告的字段补齐，不静默回退旧版 |
| 原始文件含历史标记 | 原字节不变，页面当前状态及原文生成说明共同解释 |

## 8. 本批验收标准（原定标准，实际结果见验收报告）

1. 未看开发脚本的人能从概览说明演示服务范围、阶段截止、交付构成及下一步；不把汇总授权人数当月报分母。
2. 无报告时只有真实空态，未交付草稿/approved候选不进入药企列表。
3. 在1280×720及1440×900桌面视口，当前可读报告首屏先出现状态、阶段与阅读提要，不先展示两段完整校验串；390px窄窗口维持相同优先顺序，不强求所有提要内容同时出现在一个屏高内。
4. 本次报告示例仍是问卷已保护、联系9/14、教育9/14、服务任务18/28，所有数值与原保护投影一致。
5. available/suppressed/unknown/no_applicable四种输出均有明确文案；隐藏值不经摘要/标签/颜色重现。
6. 全部40项指标及原始定义可访问；完整统计窗口与不含结束边界可核对。
7. 当前可读的已验收页不再以“待人工审核”作为当前主状态；历史生成文字仍能被明确找到。
8. 本批前后既有正文摘要、固定文本/HTML字节及文件摘要均不变；只读阅读不增加业务事件。
9. 核对提示不生成或暗示未保存的勾选记录；客户动作仍以实际版本和现有回执为准。
10. 原本验收意见可选、修改理由必填的行为及不同状态可执行动作保持一致。
11. 503精确重试、409核对、reset及撤回后的迟到响应，不会使新增区域绕过已有隔离。
12. blocked/revoked时，新提要、安排、范围、签署、摘要和下载等受控详情均不回显。
13. 390/755/1440/1920px可读、无横向溢出，键盘可访问折叠内容与所有原锚点。
14. 原患者问卷—联系—医生—教育—冻结—退回修订—双签—交付—验收主线仍可完整走通。

上述为原定成功标准；实际执行、失败排查及最终结果逐项列于本批验收报告，不以草案本身作为通过证明。
