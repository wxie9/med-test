# 乳腺癌全生命周期平台 — 全链路功能演示版 设计规格

日期：2026-10-13
状态：待项目方评审
依据：方案 v0.2、演示设计草案、Codex 复核意见（已吸收 P0 项）
项目方决定：全链路功能演示，不是幻灯片；两条临床主线、三个智能体、专家与药企两类受众都要覆盖；数据全部 mock。

---

## 1. 目标与边界

### 1.1 目标
交付一个可本地一条命令启动、可反复演示、全部功能真实可交互的 Web 原型，完整展示"患者 → 医生 → 数据治理 → 药企研究 → 试验机会回到患者"的闭环。演示受众：复旦肿瘤乳腺科专家（关注是否减轻随访负担、临床逻辑是否可信）、潜在药企（关注数据能否支持研究可行性评估与证据生成）。

### 1.2 成功标准
- 演示者按脚本 12–15 分钟走完两条临床主线和一条研究主线，全程无需解释"这里是假的"，因为每个数字都由同一套计算服务实时算出。
- 断网、无模型密钥、模型超时三种情况下演示仍能走完。
- 专家能指出至少一处"这和我们科室实际一样"，药企能看懂"符合/不符合/信息不足"的入组漏斗。

### 1.3 不做
真实 HIS/EMR 接口、真实身份认证与权限、微信小程序、真实脱敏与合规审计、多语言、移动端以外的响应式适配、生产部署。

### 1.4 功能标记约定
规格中每个功能标注三类之一：
- **[交互]** 本次真实实现、可操作、数据实时计算。
- **[模拟]** 本次实现界面与固定流程，但后端逻辑为预设（如 HIS 接口状态）。
- **[后续]** 仅在界面上以说明文字出现，不实现。

## 2. 演示故事线（全链路）

四个视角通过顶部"演示视角切换"进入，共享同一份状态，任一视角的操作在其他视角实时可见。

### 主线 A：早期乳腺癌辅助内分泌治疗管理（约 4 分钟）
锚点患者 A：52 岁，HR+/HER2-，pT2N1M0，术后辅助化疗与放疗已完成，口服 AI 类内分泌治疗第 14 个月。

1. [患者端] 患者 A 完成本月 ePRO：关节痛 2 级、潮热 2 级、过去两周漏服 5 次，停药念头"是"。
2. [系统] 规则引擎触发两条预警：症状预警（中）、依从性预警（高）。患者端显示"个案管理师将在 1 个工作日内联系您"。
3. [医生工作台] 个案管理师看到预警队列，打开患者 A 全程时间轴，查看 PRO 趋势与用药打卡，记录电话沟通，提交医生复核。
4. [医生工作台] 医生复核，调用医生助手生成"症状处理建议草稿"（引用指南要点库），确认后形成随访任务：2 周后复评，必要时门诊调整方案。
5. [患者端] 患者 A 收到处置反馈与新随访计划。预警状态变为"已关闭"。

### 主线 B：HR+/HER2 低表达晚期乳腺癌 CDK4/6 后治疗（约 3 分钟）
锚点患者 B：61 岁，初诊 III 期，术后 3 年复发伴骨转移，一线内分泌联合 CDK4/6 抑制剂进展，二线 ADC 治疗第 3 周期。

1. [患者端] 患者 B 完成治疗期周度 ePRO：恶心 2 级、乏力 2 级、口腔炎 1 级。
2. [医生工作台] 医生查看患者 B 时间轴：病理结果变化（原发 HER2 0 → 转移灶 HER2 1+），治疗事件与系统治疗线清晰分层。
3. [医生工作台] 医生助手回答"该患者当前线不良事件按 CTCAE 应如何分级并记录"，答案引用指南要点并标注来源版本。
4. [医生工作台] 医生在队列圈选中以条件"HR+/HER2 低表达、CDK4/6 经治、转移性"圈出 N 例，标记为科研候选队列并提交数据治理。

### 主线 C：数据治理与研究快照（约 2 分钟）
1. [治理工作台] 数据负责人看到候选队列，查看字段完整率、治疗线推断复核率、知情同意状态（随访服务/科研/药企脱敏三项分别统计）。
2. [治理工作台] 创建"研究快照 2026-10-13-v1"，冻结数据截止日与纳入人群。此后临床端的新操作不影响该快照。

### 主线 D：药企研究门户（约 5 分钟）
1. [研究门户] 药企研究员选择快照，查看队列概览：样本量、事件数、随访时长分布、缺失概况，所有页面带"合成数据，仅用于演示"水印。
2. [研究门户] 用例一：HR+/HER2 低表达人群 CDK4/6 后治疗模式（桑基图或序贯条图）与治疗线间状态（仍在治疗/已进入下一线/失访/死亡/信息不足，互斥）。
3. [研究门户] 用例二：虚构方案"XX-ADC-301"入组可行性。逐条入排标准展示漏斗：符合已知条件 / 不符合 / 信息不足，并列出"信息不足"的原因分布。
4. [研究门户] 研究助手回答"信息不足中最主要的原因是什么，补齐需要什么数据"，答案来自同一计算服务，并生成"补数任务"推送到治理工作台。
5. [研究门户] 用例三：辅助内分泌人群依从性与停药原因描述统计，明确标注"合成数据，关联不构成发现"。
6. [研究门户] 研究员点击"申请候选患者核查"，向科室发出匿名候选名单请求（药企不见身份）。

### 闭环回到患者（约 1 分钟）
1. [医生工作台] 医生看到候选核查请求，逐例确认，确认后向患者 B 推送"有一项临床研究可能适合您，请门诊咨询"。
2. [患者端] 患者 B 收到研究机会提示，患者管家回答"参加临床研究需要注意什么"，并引导预约门诊。

## 4. 领域模型

### 4.1 核心实体
- **Patient**：ID、年龄、入组日期、知情同意（三项布尔 + 日期）、当前阶段（早期辅助 / 转移性 / 生存期 / 失访 / 死亡）。
- **Specimen & Biomarker**：标本部位、取材日期、ER/PR（%）、HER2 IHC（0/1+/2+/3+）、ISH 结果、Ki-67、判读版本。HER2 低表达为派生字段，仅当 IHC 1+ 或（IHC 2+ 且 ISH 阴性）时派生，缺任一项则为"不可判定"。
- **Staging**：cTNM、pTNM、分期日期、分期系统版本。
- **TreatmentEvent**：类型（手术/放疗/化疗/内分泌/抗 HER2/CDK4/6/ADC/其他）、治疗意图（新辅助/辅助/转移性）、药物、起止日期、停止原因（完成/进展/毒性/患者意愿/失访/死亡/未知）。
- **SystemicTherapyLine**：由规则从转移性阶段的 TreatmentEvent 推断，记录线号、组成事件、规则版本、人工复核状态与复核人。
- **OutcomeEvent**：类型（局部复发/远处转移/进展/死亡）、日期、证据来源（影像/病理/临床记录）、判定人。
- **PROResponse**：量表 ID、提交时间、条目得分、派生分级。
- **AdherenceLog**：日期、应服/实服、漏服原因（自报）。
- **Alert**：类型、等级、触发规则、状态机（触发 → 待分派 → 已接单 → 处置中 → 待复核 → 已关闭 / 已升级）、当班责任人、各状态时间戳。
- **FollowUpTask**：类型、到期日、负责人、状态。
- **Cohort**：筛选条件 JSON、创建人、来源视角。
- **ResearchSnapshot**：快照 ID、数据截止日、纳入 Cohort、创建时间、字段完整率、质量指标，内容不可变。
- **CandidateReviewRequest**：快照、方案 ID、候选患者列表、医生逐例确认状态。
- **DataGapTask**：来源用例、缺失字段、涉及患者数、状态。

### 4.2 结局字典（演示版）
| 结局 | 索引日 | 事件证据 | 删失规则 |
|---|---|---|---|
| rwPFS（转移性，按线） | 该线首次给药日 | 影像或病理证实进展，或死亡 | 末次有效随访日 |
| 复发（早期） | 手术日 | 局部复发或远处转移事件 | 末次有效随访日 |
| 治疗线间状态 | 该线结束日 | 互斥五态：仍在治疗 / 已进入下一线 / 失访 / 死亡 / 信息不足 | 数据截止日 |

事件不足（事件数 < 10）时页面显示"不可估计"，不画曲线。

### 4.3 量表
- 内分泌维持期月度问卷：关节痛、潮热、情绪、睡眠、依从性四题、停药念头。标注"演示用自拟问卷，非标准量表"。
- 治疗期周度问卷：恶心、乏力、口腔炎、腹泻、手足综合征、发热。同样标注。
- 不使用 EORTC/PRO-CTCAE 原题，避免版权问题；界面说明"正式版将采用已授权标准量表"。

## 5. Mock 数据设计

### 5.1 三层结构
1. **锚点病例（12 例，手工编写 JSON）**：患者 A、患者 B，加 10 例覆盖：新辅助后 pCR、三阴性早期、HER2+ 转移一线、原发与转移 HER2 结果不一致、外院治疗信息不全、内分泌 5 年完成进入生存期、失访、死亡、停药原因缺失、晚录入检测结果。每例附一句"专家审阅要点"。
2. **批量合成队列（约 2000 例，生成器产出）**：受疾病状态机与时间约束，不独立随机。
3. **异常测试病例（约 20 例）**：日期倒置、重复事件、缺失分期等，用于验证质量指标与"信息不足"路径，默认不进演示队列。

### 5.2 生成器约束
- 固定随机种子、生成器版本号、配置文件，三者相同则输出校验值相同。
- 分子分型分布：HR+/HER2- 约 65%、HER2+ 约 20%、三阴性约 15%；HER2 IHC 分布按低表达约 50% 设计，超低表达单独标记。
- 阶段转移概率按分期与分型设置；复发时间服从参数化分布；死亡只能在进展或复发之后。
- 治疗事件必须满足：意图与阶段一致，起止不重叠（允许内分泌与 CDK4/6 联合），停止原因与后续事件一致。
- 不完美注入：约 8% 患者缺停药原因，约 5% 缺 ISH，约 10% 外院治疗仅有药名无日期，约 6% 失访。
- 依从性：仅生成自报打卡，不生成 PDC/MPR。
- 明确禁止：生成器不得内置"依从性好 → 复发少"的因果关系；若需展示相关图，标题必须写"合成数据，关联不构成发现"。

### 5.3 数据文件
- `data/seed/anchors.json`、`data/seed/cohort.json`、`data/seed/edge-cases.json`、`data/seed/manifest.json`（种子、版本、校验值、数据截止日）。
- 运行时交互状态（预警、任务、快照等）存于内存状态容器，支持"一键重置到种子状态"；可选落盘到 SQLite（`DEMO_PERSIST=1`）。

## 6. 智能体设计

### 6.1 原则
- 默认**确定性演示模式**，在线模型为可选增强；界面始终显示当前模式。
- 任何数字（人数、比例、分级）必须来自计算服务工具调用，模型不得自行生成。
- 高风险症状、预警触发、入组判定由批准的规则执行，模型只负责措辞与解释。
- 每个助手的快捷问题与当前页面上下文绑定（当前患者、当前筛选、当前快照），自由输入保留。

### 6.2 三个助手
| 助手 | 上下文 | 工具 | 边界回答 |
|---|---|---|---|
| 患者管家 | 当前患者、最新 PRO、随访计划 | 读取计划、读取处置反馈、预约引导 | 用药调整、剂量、是否停药 → "请与医生确认"，并给门诊路径 |
| 医生助手 | 当前患者时间轴、指南要点库 | 病历摘要、指南检索（带来源与版本）、建议草稿、CTCAE 分级查询 | 无匹配依据时明确"未找到依据" |
| 研究助手 | 当前快照、当前筛选、用例结果 | 队列计数、漏斗分解、缺失原因、生成补数任务 | 超出快照范围的推断 → 说明数据不支持 |

### 6.3 模型适配层
- 接口：`chat(messages, tools, context) → {text, toolCalls, citations}`。
- 提供商：`claude`（默认，服务端密钥）、`openai-compatible`（base URL + model 配置，覆盖国产模型）、`deterministic`（本地模板）。
- 降级触发：无密钥、网络错误、401/403、429、超时（8 秒）、输出结构校验失败、引用不存在。降级后保留会话状态并提示"已切换至本地演示模式"。
- 确定性模式实现：按（助手、页面、快捷问题、上下文摘要）匹配模板，模板中的数字槽位由计算服务填充，不同患者或筛选输出不同答案。

### 6.4 指南要点库
约 30 条乳腺癌诊疗要点，字段：要点文本、主题标签、来源名称、版本、适用人群、备注。来源以"CSCO 乳腺癌诊疗指南（版本）要点转述"方式记录，不复制原文大段内容。

## 7. 预警与任务状态机

```
触发 → 待分派 → 已接单 → 处置中 → 待复核 → 已关闭
                 └──超时未接单（高级 2 小时 / 中级 24 小时）──► 已升级（通知科室负责人）
```
- 规则（演示版）：任一症状 ≥ 3 级为高；两周漏服 ≥ 3 次或停药念头为高；任一症状 2 级为中。
- 非服务时段（演示用 18:00–08:00）提交高风险预警时，患者端显示急诊提示与值班电话（mock）。
- 指标面板：按等级的首响应时长 P50/P90、逾期未处理数、本周关闭数。

## 9. 技术架构

- Next.js（App Router）+ TypeScript，Tailwind，Recharts。
- 单仓库结构：`app/`（页面）、`lib/domain/`（实体与规则）、`lib/compute/`（队列、漏斗、结局、质量指标）、`lib/agents/`（适配层、模板、工具）、`lib/state/`（状态容器与重置）、`scripts/generate-seed.ts`、`data/seed/`、`docs/demo-script.md`。
- 所有视角通过 `lib/compute` 取数，禁止页面内写死数字。
- 密钥只在服务端环境变量；浏览器不接触模型接口。
- 测试：Vitest 覆盖生成器约束、治疗线推断、漏斗计算、状态机、降级逻辑；Playwright 覆盖完整故事线一轮。

## 10. 验收标准

| 对象 | 标准 |
|---|---|
| 启动 | README 步骤后 `npm run demo` 一条命令启动；首次启动自动生成种子数据 |
| 离线 | 无密钥、断网下四个视角完整故事线可走完，助手显示本地演示模式 |
| 数据复现 | 相同种子/配置/版本两次生成校验值相同；时间与状态硬约束违规为 0（生成器自检输出） |
| 闭环 | 患者 A 提交一次 ePRO 只产生对应的两条预警；处置后患者端同步；关闭必须有处置记录 |
| 统计一致 | 五组固定筛选条件的预期人数写入 `data/seed/expected.json`，页面、导出、研究助手三处一致 |
| 入组判定 | 三态互斥展示；任一条件缺失不得判为符合 |
| 快照 | 创建快照后，临床端新增事件不改变快照内任何数字 |
| 降级 | 注入超时、401、429、非法输出四种故障，10 秒内切换，无未处理异常 |
| 助手边界 | 每个助手至少 3 个正常问题、1 个超范围问题、1 个无依据问题有预期答案，不编造事实与数字 |
| 稳定性 | 连续三轮完整演示并重置，无重复事件、无旧筛选残留 |
| 投屏 | 1920×1080 与 1440×900 下无横向滚动、字号可读 |
