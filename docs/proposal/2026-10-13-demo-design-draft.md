# 演示版设计草案（待 Codex 复核与项目方确认）

日期：2026-10-13
前置：v0.2 方案已收敛；项目方确认当前交付物是 mock 数据的演示版，科室合作形式为科研合作/共建，尚无大模型选型，尚无意向药企。

## 1. 目标与受众
可现场演示的乳腺癌全生命周期平台原型，面向复旦肿瘤乳腺科专家与潜在药企，讲清"患者数据闭环如何变成研发证据"。不接真实系统、不上线、不处理真实患者数据。

## 2. 产品形态
单一 Web 应用，顶部切换三个角色视角；患者端在页面内以手机外框渲染，不做真实微信小程序。
- 患者端：随访计划、症状上报问卷（ePRO）、用药打卡、预警反馈、匹配到的试验与援助。
- 医生工作台：科室患者列表、单患者全程时间轴、预警处置队列、队列圈选导出。
- 药企研究门户：队列概览、HER2 低表达治疗模式、ADC 序贯结局、内分泌依从与复发、治疗线流失、入组可行性估算、分析沙箱占位。

## 3. Mock 数据
可复现的合成数据生成脚本，约 2000 例乳腺癌患者：分子分型、TNM 分期、治疗线（手术、放化疗、内分泌、抗 HER2、CDK4/6、ADC）、复发/转移事件、周度或月度 PRO 时间序列、内分泌依从性与停药原因、基因检测结果。固定随机种子；落盘为 JSON 或 SQLite，前端直接读。

## 4. 智能体
三个对话入口：患者管家、医生助手、研究助手。后端模型适配层，默认 Claude API，配置可换任何 OpenAI 兼容协议的国产模型；无 API key 时降级为预置脚本回答。医生助手挂小型 CSCO 乳腺癌指南要点库做检索增强。

## 5. 技术栈
Next.js + TypeScript 全栈，Tailwind，Recharts，数据生成脚本用 TypeScript。单仓库、一条命令启动。

## 6. 不做
真实 HIS 接口、登录与权限、微信小程序、真实脱敏与审计、移动端以外的性能优化。

## 7. 验收
一条命令启动后，三个视角走完完整故事线：患者上报症状触发预警 → 医生处置并圈出队列 → 药企看到该队列的治疗模式与入组可行性；三个智能体各能回答两到三个典型问题。
