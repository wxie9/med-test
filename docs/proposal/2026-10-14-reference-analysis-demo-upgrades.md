# 参考材料分析：对 Demo 的优化建议

日期：2026-10-14
材料：深至科技《业务与盈利模式解读》（2026-07）、《公司介绍》（2026-07）、机器之心《AI患者管理驶入深水区》（2026-08）、第一财经《医疗AI进入"疗效交付"周期》（2026-04）、艾诺森《氢离子——医生版GPT》（2026-07）、AI小医《2026美国AI医疗Top30》（2026-08）、动势科技里程碑（2025-12）、团队备注与"公司发展关键里程碑规划"表。

## 1. 深至的业务框架（与 Demo 对照的基准）

| 深至产品 | 定位 | 对应我们的 Demo 视角 | 现状 |
|---|---|---|---|
| Cx 橙欣健康 | 患者 7×24 健康管家：用药打卡、随访互动、AE 管理、千人千面患教；"AI 管日常、医生管风险" | 患者端（小程序外框） | ePRO、打卡、计划、消息、管家已有；患教推送、矩阵定位、脱落风险没有 |
| Dx 暖欣健康 | 医生 AI 临床伙伴：循证决策支持、院外数据回流、医嘱转为执行指令 | 医生工作台 + 医生助手 | 预警闭环、时间轴、建议草稿已有；循证溯源弱于氢离子/OpenEvidence 的"动态证据定位" |
| Px 信欣健康 | 药企疗效归因与洞察平台：PSP 归因（PSM/DiD，48 小时报告）、RWE、IIT、招募、PV、医保谈判 | 数据治理 + 药企研究门户 | 描述性用例、入组漏斗、候选核查已有；**疗效归因、项目看板、月度报告、PV 信号全部没有** |

深至的盈利三阶段：医生决策流入口（换数据）→ 患者 DOT 闭环（证明效果）→ RWE 数据授权 + 风险共担（高毛利）。我们的 Demo 覆盖了阶段一和阶段三的雏形，**阶段二"用数据证明药品疗效、延长 DOT"是空的**，而这恰是朱博"药物上市后全生命周期管理"的核心卖点，也是机器之心稿里唯一给出落地数字的部分（依从性提升 22%，AI 组 DOT 延长 ≥2 个月）。

团队备注中"到底卖什么给客户"的答案，材料里已经写得很清楚：**卖可量化的 PSP ROI 和可审计的 RWE 证据包**，患者端和医生端是证据的生产工具。Demo 的叙事重心应随之从"数据闭环"转到"疗效交付"。

## 2. 建议改进项（按对药企演示的价值排序）

### P0 — 新增研究用例"PSP 疗效归因"
- 内容：合成一个"AI 管理组 vs 常规随访组"的标记（入组 Cx 管理的患者 vs 未入组），输出三个指标：内分泌依从率、DOT（用药持续时间）中位延长、12 个月停药率；展示 PSM 平衡表（标准化差异）、DiD 估计与置信区间、依从曲线（Kaplan-Meier 风格的"仍在治疗比例"）。
- 必须标注"合成数据，仅演示归因方法，不构成疗效结论"，生成器不得内置组间效应（或内置一个可配置、文档公开的效应量，并在页面写明）。
- 配套：一键导出"PSP 月度归因报告"（Markdown/PDF），对应深至"月度报告向药企反馈"和"48 小时归因报告"的承诺。
- 价值：直接回答药企"投入能否量化回报"，是三份材料里反复强调的购买理由。

### P1 — 药企视角改为"项目"组织
- 研究门户增加"项目看板"：一个虚构 PSP 项目（药品 X、适应症、入组目标、已入组、随访完成率、缺失率、本月预警处置数、下次报告日期）。现有的快照、用例、候选核查挂在项目下。
- 命名对齐：导航上把四个视角标注为 Cx / Dx / Px 对应关系，演示时用深至自己的语言。
- 价值：对齐"药企定制化项目服务、先搭全 Agent 链路再补人工节点"的交付逻辑；治理台的补数任务就是"人工节点"。

### P1 — 患者矩阵定位与千人千面患教
- 在患者端首页和医生患者详情显示"当前格：治疗阶段 × 分子分型"（Luminal A / Luminal B HER2− / Luminal B HER2+ / 三阴性），这是机器之心稿里 Cx 的核心设计。
- 按格推送 1–2 条患教卡（合成内容，标"待专家审阅"），并加"早晚问候"一条。
- 新增"脱落风险"分级（由漏服次数、停药念头、症状等级、副作用归因组合），在医生预警队列中作为排序依据之一。
- 价值：把"管得住"的机制可视化，对应 Cx 次日留存 >70% 的叙事。

### P2 — 医生助手循证溯源升级
- 引用展示从"G-014 · CSCO 2026"升级为"支撑句 + 来源 + 版本 + 是否仍为现行推荐"，对标氢离子"动态证据定位"与 OpenEvidence 的可点击溯源。
- 患者详情增加"院外数据回流"区块：最近 ePRO、打卡、预警处置摘要，强调 Dx 看到的是院内系统没有的信息。

### P2 — 质量与运营指标补齐
- 治理台质量卡增加随访完成率、缺失率、护士工时基线（合成），对应深至与 B 医院合作中的可量化指标。
- 研究门户依从性页增加"依从曲线"（随治疗月数的仍在治疗比例）。

### P3 — 药企服务广度的占位
- PV 安全性信号：按药物类别汇总 PRO 不良事件分级，输出"季度安全性摘要"占位页，标 [后续]。
- 医保谈判证据包、IIT 支持：说明页 [后续]。
- 入口来源：患者时间轴加"基层超声终端筛查（BI-RADS 4A）"作为第一条记录，呼应 3.5 万终端入口；仅为数据字段，不做筛查功能。

## 3. 不建议采纳或需谨慎的点
- 不要引用深至公开数字（22%、≥2 个月、15000 用户）作为 Demo 数据；Demo 全部合成，数字必须由生成器产出并在页面标注。
- 不要让药企端看到患者个体数据，深至自己也强调"数据不出院、能力可复用"；现有隐私边界（研究端只有计数）要保持。
- 动势科技文章是通用 Agent 咨询公司的里程碑，与本 Demo 无直接关系；美国 Top30 榜单只作对标语言（Hippocratic AI 的"非诊断、安全架构"、OpenEvidence 的"溯源"、Tempus 的"数据平台"）。
- "氢离子"所在的阿里健康是 Dx 端潜在竞争对手；Demo 的医生助手不要试图做文献检索，守住"围绕本患者院外数据 + 指南要点"的差异化。

## 4. 建议的演示叙事调整
1. 开场用深至的话：80% 的治疗在院内，80% 的康复在院外；39.1% 的患者未完成五年内分泌治疗。
2. 患者端讲"矩阵定位 + 每天帮到一次"。
3. 医生端讲"AI 管日常、医生管风险"，预警闭环与医嘱回流。
4. 治理台讲"数据不出院、能力可复用"。
5. 药企端先看项目看板，再看 PSP 归因报告（P0），最后才是入组可行性与候选核查。
6. 收尾回到阶段三：RWE 授权与风险共担的入口在哪里（快照 + 证据包导出）。
