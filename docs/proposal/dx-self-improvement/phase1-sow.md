# DX 共用持续改进框架首期架构设计与最小闭环验证

版本：统一口径首期范围收敛稿。更新日期：2026-10-21。

## 一、项目目标与合作方式

完成 DX 共用持续改进框架的总体架构与核心机制设计，支持临床 Agent／工作流优化及软件开发、bug 修复两类任务共用实验管理与过程追溯底座，并由工程团队实施最小技术闭环验证。

采用**顾问牵头设计、实施指导与技术评审，工程团队负责工程实现与验证，项目方负责资料与环境协调、业务／专业要求确认及阶段交付接收**的合作方式。

顾问交付以架构、机制、流程、验证方案、技术审阅和交接材料为主；工程团队提交约定范围内的实现与验证成果。业务与专业判断由项目方指定的责任人员确认。

## 二、工作内容

### 1. 总体架构与首期范围设计

- 梳理可获得的 DX 系统、模型服务、工作流资产、代码仓库及评估条件，明确基础、依赖及待确认事项。
- 设计任务与基线管理、候选生成、隔离执行、轨迹记录、评估选择、评审发布及回退等逻辑模块。
- 明确共用底座与两类任务适配之间的关系，区分业务资产、改进执行器、探索策略及评估器。
- 确定首期最小范围、现有系统接入边界、设计假设及后续扩展位置。

### 2. 核心对象与管理机制设计

- 定义任务、基线、候选、执行、评估、决策与发布资产之间的关系。
- 明确可修改范围、执行权限、实验预算、停止条件和受保护的评估依据。
- 设计改进假设、历史轨迹、经验结论及可复用机制的记录、审阅与版本管理原则。
- 明确执行成功、质量合格、搜索采纳与正式发布的状态区分。
- 定义历史回放所需的记录结构、适用条件和扩展原则。

### 3. 关键流程与接口约定设计

- 设计任务与候选流程：问题登记、基线确认、候选提出、隔离执行、评估比较及采纳或保留原版本。
- 设计两类任务的执行与评估适配、测量有效性、回归检查、资源记录及证据不足处理。
- 设计评审发布与回退流程：人工评审、组合依赖检查、版本发布及恢复。
- 设计异常与追溯流程：失败、有限重试、中断恢复、重复提交及版本关联。
- 明确接口原则、预期行为与验证记录要求，区分框架、任务改进、机制泛化及临床效果评价。

### 4. 工程实施指导与技术评审

- 向工程团队说明总体架构、核心机制和接口约定。
- 评审约定范围内的工程实现方案，识别与设计不一致的部分。
- 对实施中的架构、接口、运行配置及范围变化提出处理建议。
- 根据评审与验证结果修订设计，记录关键决策、处理结论和遗留事项。

### 5. 最小闭环验证与交接

- 定义两类任务的最小代表路径、验证场景与预期行为。
- 指导工程团队使用抽象任务、模拟资产或具备条件的实际任务，验证候选执行、评估比较、采纳或保留基线及过程追溯。
- 审阅不合格候选阻断、无效评估处理、有限重试、中断恢复、重复提交及发布回退核心状态的验证结果。
- 按验证结果修订设计，整理已验证与未验证内容、已知限制和后续依赖，完成讲解及交接。

## 三、阶段交付物

### 1. 顾问牵头交付

| 交付物 | 主要内容 |
| --- | --- |
| 《DX 首期总体架构与范围说明》 | 架构图、模块职责、共用底座与两类任务适配关系、接入边界、首期范围、设计假设及依赖 |
| 《DX 核心机制、流程与接口约定》 | 核心对象关系、任务与基线约定、候选与执行生命周期、隔离与权限、轨迹与版本、评估选择、评审发布与回退流程及回放扩展约定 |
| 《DX 框架验证方案与技术评审记录》 | 两类代表路径、验证场景与预期行为、工程方案评审意见、过程与结果审阅结论、问题处理记录 |
| 《DX 首期总结与交接说明》 | 最终设计结论、已验证与未验证内容、已知限制、遗留事项及后续建议 |

上述内容可合并成统一文档包，不要求拆成多个独立文件；各项内容按约定阶段形成、评审和修订。

### 2. 工程团队配套交付

**最小框架实现与验证包**包括：

- 约定范围内的源代码、配置模板及运行说明。
- 最小接入或任务适配、抽象／模拟输入、接口桩及验证用例。
- 核心流程运行记录、版本关联、验证结果及异常处理记录。
- 问题修复记录、必要的恢复或回退说明及已知工程限制。

工程成果由工程团队实施并提交，顾问负责设计指导与技术审阅；实现边界以本项目首期范围说明为准。

## 四、首期范围与验证边界

首期以**共用实验管理底座、两类任务最小适配、固定且受限的探索策略、实际执行与评估比较、人工评审及可追溯版本闭环**为实施基线。优先采用简单、可复现的工程结构，逻辑模块可合并实现。

历史回放在首期完成记录与接口原则设计。基于合格历史、使用预设策略的有限回放验证作为条件具备后另行确认的扩展项，不纳入默认最小工程交付。

自动生成探索策略、自动修改改进执行器、模型权重训练、开放式自修改、无人评审正式发布、大规模跨院实施、生产高可用及长期运维后置或另行约定。

本期聚焦框架与流程，暂不细化患者数据字段、具体临床业务功能和专用算法。框架验证使用约定环境、抽象或模拟输入及具备条件的接口，记录实际验证层级。

框架交付关注流程可验证、结果可追溯及边界明确。真实数据适配、实际院内联调、生产实施和临床效果评价在条件具备后另行明确；DX 的任务收益和机制泛化亦需独立证据。

本版暂不确定具体时间与费用。并行推进与顺序推进仅调整组织和阶段衔接，均沿用本项目相同首期范围及交付要求。
