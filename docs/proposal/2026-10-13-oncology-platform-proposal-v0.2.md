## 1. 一句话定位

> 以复旦肿瘤医院乳腺科为锚点，建设乳腺癌患者"诊断—治疗—随访—生存期—复发"全生命周期的合规数据闭环与管理服务；向药企提供研究可行性评估与证据生成流程、试验入组与上市后研究支持，证据的监管适用性按项目逐一确认；智能体贯穿患者、医生、研究三端。

---

## 2. 为什么乳腺癌是最好的起点

| 理由 | 依据 |
|---|---|
| 生存期长，全生命周期管理价值最大 | 早期乳腺癌内分泌治疗需 5–10 年，真实世界 30%–50% 患者在 5 年疗程内提前停药 | 
| 依从性是可量化、可改善的痛点 | 症状是提前停药主因；多项研究用 ePRO + 护士主导症状管理提升依从 ([Springer](https://link.springer.com/article/10.1007/s00520-024-08547-7)、[PMC](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11090970/)) |
| 药企管线最密集、问题最多 | CSCO 2026 指南将 T-DXd 列为 CDK4/6 经治后 HR+/HER2 低表达 I 级推荐，Dato-DXd II 级；HER2 低表达/超低表达、TROP2 ADC 序贯、耐药机制均是在研热点 ([药渡云](https://www.pharnexcloud.com/zixun/shiye/lcyj_305203)、[NCT07368543](https://clinicaltrials.gov/study/NCT07368543)、[NCT05824325](https://clinicaltrials.gov/study/NCT05824325)) |
| 国内 RWE 证据稀薄 | 国内 ADC 真实世界比较多为单中心回顾（如 301 医院 220 例 T-DXd vs TROP2 ADC） ([解放军医学院学报](https://xuebao.301hospital.com.cn/article/doi/10.12435/j.issn.2095-5227.26032302))，多中心前瞻性纵向数据缺口明显 |
| 上海商保已有乳腺癌专项产品且缺数据 | 太保与上海临转院的"申爱保·乳腺癌复发保障险"2025 年 6 月上线，报道明确指出缺乏高质量数据时定价容易亏损 ([澎湃](https://www.thepaper.cn/newsDetail_forward_30698274)、[新民周刊](https://img1.xinmin.cn/xmzk/2025-11-24/241124.pdf)) |
| 国际药企用例成熟可复制 | Flatiron 数据用于 HER2+ 一线治疗模式与 DESTINY-Breast09 入组标准对照（ISPOR 2026）；欧洲 EMR 研究治疗线间流失；PRAEGNANT 登记研究序贯疗效 ([ISPOR](https://www.ispor.org/heor-resources/presentations-database/presentation-cti/ispor-europe-2026/poster-session-5-4/treatment-patterns-and-outcomes-in-patients-with-her2-positive-metastatic-breast-cancer-treated-with-first-line-taxane-trastuzumab-and-pertuzumab-a-2012-2024-us-real-world-analysis)、[PMC](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11785661/)) |

## 3. 目标用户与价值

| 用户 | 要解决的问题 | 平台提供 |
|---|---|---|
| 乳腺癌患者/家属 | 术后与内分泌治疗期症状困扰、停药、复查遗漏、信息焦虑 | 个性化随访计划、ePRO 症状上报与预警、用药提醒、康复与科普、试验与援助机会 |
| 复旦肿瘤乳腺科医生/个案管理师 | 门诊量大、随访人工成本高、PRO 纸质难收、科研数据零散 | 患者全程视图、预警工作台、随访任务流、科研队列一键导出、MDT 资料包 |
| 药企医学/临床运营/HEOR | 国内乳腺癌纵向 RWE 缺、入组慢、上市后证据要求提高（ICH M14） | 队列描述与治疗模式、外部对照/试验模拟、入组可行性与匹配、PMS/PASS 项目管理、分析沙箱 |
| 商保（后期） | 复发险定价缺数据、院外履约难核验 | 脱敏聚合的复发与结局数据、院外管理履约记录 |

## 4. 产品架构（四层 + 智能体横切）

```
┌───────────────────────────────────────────────────────────────┐
│  智能体层（横切）：患者管家 │ 医生助手 │ 研究助手（NLP 结构化、队列问答）│
├───────────────┬───────────────────┬───────────────────────────┤
│ 患者端         │ 临床端             │ 研究端                     │
│ 微信小程序     │ 医生/个案管理工作台 │ 药企研究门户 + 分析沙箱      │
│ ePRO/依从/提醒 │ 全程视图/预警/随访  │ 队列/治疗线/结局/入组匹配    │
├───────────────┴───────────────────┴───────────────────────────┤
│  数据底座：乳腺癌专病数据模型 │ 存量数据接入 │ HIS/EMR 接口 │ NLP 抽取│
│            知情同意与授权 │ 脱敏分级 │ 审计与溯源 │ 质量指标        │
└───────────────────────────────────────────────────────────────┘
```

### 4.1 数据底座（第一优先级）

- **乳腺癌专病数据模型**：以国际通用的观察性数据模型为骨架（如 OMOP 风格），叠加乳腺癌专属字段：
  - 分子分型：ER/PR/HER2（含 HER2 低表达、超低表达）/Ki-67，基因检测（BRCA1/2、PIK3CA、ESR1 等）
  - 分期与病理：TNM、组织学、淋巴结、切缘
  - 治疗线：手术、放疗、新辅助/辅助化疗、内分泌、靶向（抗 HER2、CDK4/6）、ADC，每线起止、方案、停药原因
  - 结局事件：复发、转移、进展、死亡、不良事件（CTCAE 分级）
  - 患者报告：EORTC QLQ-C30/BR23（或 BR45）、PRO-CTCAE、依从性量表
- **存量数据接入**：先做数据盘点（来源、字段、授权状态、时间跨度、质量），映射到专病模型，形成回顾性队列。这是 MVP 的第一个交付物。
- **治疗线推断**：规则引擎 + NLP 抽取 + 人工复核三层，复核率与一致性作为质量指标对外公开。
- **合规**：逐项知情同意（随访服务、科研使用、药企脱敏使用分开勾选）；基因组数据不出境；药企只能在沙箱内分析或获取脱敏聚合结果；审计日志与数据溯源对齐 NMPA 真实世界研究检查要点与 ICH M14。

### 4.2 患者端（微信小程序）

- 入组：科室扫码/个案管理师邀请，绑定病历。
- 随访计划：按分期、分子分型、当前治疗线自动生成（参考 CSCO/CBCS 指南与科室规范），复查与用药节点提醒。
- ePRO：治疗期每周、内分泌维持期每月，症状分级触发预警。
- 依从性：内分泌用药打卡与停药原因采集。
- 信息与机会：科室审核的科普、康复指导、匹配到的临床试验与援助项目（需医生确认后推送）。

### 4.3 临床端（医生/个案管理师工作台）

- 患者全程视图：时间轴展示治疗线、事件、PRO 趋势。
- 预警工作台：按严重度排序的症状预警，处置记录闭环。
- 随访任务流：到期随访、失访召回、复查提醒。
- 科研支持：按条件圈选队列、导出脱敏数据、MDT 资料包生成。

### 4.4 研究端（药企研究门户）

- 队列浏览与描述统计（脱敏聚合）。
- 治疗模式与治疗线流失分析、结局分析（PFS/OS/复发）。
- 试验入组可行性评估与候选患者匹配（候选由医生确认，药企不见个体身份）。
- 项目管理：上市后研究（PMS/PASS）、患者支持项目的进度与质量看板。
- 分析沙箱：药企分析人员在平台内运行分析，结果经审核后导出。

### 4.5 智能体层

| 智能体 | 面向 | 能力 | 边界 |
|---|---|---|---|
| 患者管家 | 患者 | 症状问答与分诊建议、用药与复查提醒、科普解答 | 不做诊断与处方，高风险症状直接转人工 |
| 医生助手 | 医生 | 指南检索（CSCO/CBCS）、病历摘要、随访建议草稿、PRO 趋势解读 | 输出为草稿，医生确认后生效 |
| 研究助手 | 数据/药企 | 病历 NLP 结构化、自然语言队列查询、分析报告草稿 | 仅在脱敏数据与沙箱内运行 |

模型部署建议私有化（院内或企业 VPC），优先国产医疗大模型或开源模型微调，避免患者数据外流。

## 5. 药企用例清单（MVP 起即可演示）

1. HR+/HER2 低表达人群在 CDK4/6 抑制剂后的治疗模式与结局描述。
2. ADC 序贯（T-DXd 与 TROP2 ADC）的真实世界比较与耐药后路径。
3. 辅助内分泌治疗依从性与停药原因，及其与复发的关联。
4. 治疗线间流失率（attrition），用于估算后线试验可及人群。
5. 外部对照臂与试验模拟：用真实世界队列对照既有 III 期入组标准。
6. 入组可行性与招募：按入排标准估算科室可入组人数并匹配候选。
7. 上市后安全性信号监测（ICH M14 框架下的非干预性研究）。

| 指标 | 目标 |
|---|---|
| 回顾性队列规模 | 视存量数据而定，目标 ≥ 3000 例可用病例 |
| 前瞻管理患者 | 500–1000 例 |

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 存量数据授权不清，无法用于科研或药企 | Phase 0 逐批核验授权来源；处理依据或批准用途未核实的数据隔离封存，不进入调试、训练、演示或研究；开发阶段只使用合成数据 |
| 单中心偏倚（复旦肿瘤患者更晚期、更复杂） | 研究端明确标注来源与人群特征；Phase 3 扩中心 |
| 长期随访流失 | 个案管理师人工触达、与复查挂钩、小程序低门槛 |
| 遗传资源与数据出境 | 基因数据院内留存，跨境药企只拿脱敏聚合结果 |
| 医疗 AI 责任 | 智能体仅辅助，所有临床输出医生确认；留痕可追溯 |
| 医院信息科接口推进慢 | MVP 以存量数据 + 患者上传 + 科室导出为主，HIS 接口放 Phase 2 |
| 药企合作停留在免费联合研究 | Phase 2 起设计付费项目模板（PMS、招募、数据授权），为 Phase 3 商业化铺路 |

## 8. 技术方向（初步，待规格阶段细化）

- 患者端：微信小程序。
- 临床端与研究端：Web 应用。
- 数据底座：关系型数据库 + 数据仓库，专病模型与 OMOP 风格映射，审计日志独立存储。
- NLP 与智能体：私有化部署的大模型 + 检索增强（指南库、科室规范），结构化抽取任务配人工复核界面。
- 部署：院内或企业私有云，药企沙箱与生产数据物理隔离。

## 9. 仍需确认的问题（进入规格前）

1. **存量数据**：数据类型（病历、随访、PRO、基因、影像）、规模、时间跨度、来源医院、现有授权与伦理状态。
2. **科室合作形式**：科研课题合作、专病数据库共建，还是信息化采购？决定伦理路径与数据归属。
3. **团队与技术能力**：现有研发团队规模、是否有医疗信息化与 NLP 经验、是否已有模型选型。
4. **智能体模型选型**：是否有指定的国产大模型或私有化要求。
5. **首批药企目标**：是否已有意向药企或产品（如 ADC、CDK4/6 厂商），以便优先构建对应用例。
